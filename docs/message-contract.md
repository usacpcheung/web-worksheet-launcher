# Message Contract (Phase 1)

This document defines the launch-hash contract and postMessage contract between:

- **Parent app** (`parent_prototype/parent.html`)
- **Popup renderer** (`server/worksheet_launcher/render.html`)

## 1) Launch hash contract

The popup URL hash **must** follow:

`#w=<base64url>&rid=<id>&returnOrigin=<origin>`

Where:

- `w`: base64url-encoded JSON worksheet payload
- `rid`: request identifier generated by parent
- `returnOrigin`: parent origin used as `postMessage` target origin

Example shape:

`https://<host>/worksheet/render.html#w=<base64url>&rid=<id>&returnOrigin=<origin>`

## 2) Worksheet payload schema (`w` decoded)

```json
{ "v": 1, "title": "string", "q": ["...1-5"], "rewrite": true }
```

Validation rules:

- `v` must equal `1`
- `title` should be a string when present
- `q` must be an array of strings with length `1..5`
- `rewrite` should be a boolean when present

## 3) Popup → parent message schema

```json
{
  "type": "worksheetResult",
  "rid": "...",
  "worksheet": { "v": 1, "title": "...", "q": ["..."] },
  "answers": [{ "index": 0, "question": "...", "raw": "...", "rewritten": "..." }],
  "meta": { "sentAt": "ISO-8601" }
}
```

Notes:

- `type` is fixed to `worksheetResult`
- `rid` must echo the launch `rid`
- `meta.sentAt` is an ISO-8601 timestamp string

## 4) Parent validation requirements (must enforce)

On `message` events, parent must reject payloads unless **all** pass:

1. `event.origin` exactly matches the trusted renderer origin
2. `event.data.type === "worksheetResult"`
3. `event.data.rid` equals the outstanding request id (`rid`) used to launch popup

If any check fails, ignore message and do not apply results.

## 5) Phase boundary

Phase 1 only defines contracts/scaffolding.
No new runtime behavior is introduced by this document.
